# Независимая проверка изменений

Проверка выполнена отдельным агентом по фактическому исходному коду и согласованной спецификации. Тесты не заменяли ревью.

## Найдено и исправлено

1. Конкурирующие сохранения могли терять правки при сообщении об успехе. Теперь операции импорта, анализа и сохранения выполняются последовательно; редактор сбрасывается при замене результата.
2. Старый черновик мог пережить повторный анализ с теми же идентификаторами шагов. Добавлена ревизия анализа и блокировка переходов во время операции.
3. Большой файл уходил на сервер до проверки. Ограничение проверяется в browser, при чтении тела запроса и при разборе файла/распаковке DOCX.
4. Метрики принимали обрезанные цитаты без «до», «не менее», части диапазонов и цифр. Проверяется окружающий контекст исходника; составное время поддерживается.
5. Почасовой тариф принимался за абсолютную стоимость потери. Тарифы исключены, для суммы требуется основание.
6. В банковском демо длительность первичной проверки ошибочно использовалась как потеря повторной работы. Первичная проверка — 12 минут, повторная — неизвестно.
7. Подтверждённая экономия времени всегда оставалась null. Теперь измеренный результат с цитатой и основанием поддерживается, прогнозы не выдаются за замеры.
8. Предпросмотр отчёта показывал экранирование Markdown/HTML. Текст безопасно декодируется и отображается средствами React.
9. Статус настроек ИИ ошибочно обещал подключение. Теперь он сообщает только о наличии конфигурации; успешность реального API проверяется отдельным запросом анализа.

## Результат повторного ревью

Все перечисленные замечания закрыты. После отдельного ревью количественного ритейл-примера независимо проверены 61 backend-тест и 6 frontend-тестов; существенных замечаний в проверенном объёме не осталось. Проверка реального провайдера не выполнялась — ключ и провайдер пока не выбраны. Production build прошёл. Браузерная приёмка включала три примера, импорт TXT/DOCX, отклонение вымышленной цитаты, сохранение правки, выгрузки текущего состояния и мобильный экран. Подробности в docs/progress.md, локальные артефакты в output/qa.

Ограничение: точное совпадение цитаты и проверка численного контекста не доказывают смысловую корректность каждого вывода. Результат требует проверки человеком.

## Проверка дополнений по кейсу AXENIX 24 ноября 2026

Добавлены одностраничный A4 PDF, скачиваемый учебный TXT и контрактная проверка трёх потерь и трёх предложений с подтверждёнными замерами. Подробный Markdown сохранён; полные данные находятся в JSON. PDF проверен на трёх демопримерах, живом результате, длинных полях и неполном разборе. Учебная маркировка сохраняется и при живом анализе подготовленного TXT.

Для ответов модели добавлены восстановление регистра по единственному точному совпадению без учёта регистра и одна коррекция по диагностике валидации. Изменения слов, пунктуации, неподтверждённые метрики и неоднозначные цитаты не принимаются. Все строгие проверки выполняются повторно. Доступ и транспортные ошибки не запускают коррекцию.

Независимый reviewer проверил PDF, сценарий, тесты и изменения валидации: существенных замечаний нет. Исправлено замечание о полноте экспорта: только JSON содержит полный набор оснований.

Итог: 82 backend-теста, 10 frontend-тестов, production build, pip check и git diff --check прошли. Браузерный прогон: 39 проверок, пять ширин от 320 до 1440 px, скачивание TXT/PDF, повтор после ошибки сети, живой разбор с четырьмя потерями и тремя предложениями за 49,5 секунды. Артефакты — output/case-fixes/ и output/pdf/axenix/.

## Исправление анализа пользовательских стенограмм 25 ноября 2026

Воспроизведены повторяющиеся неподтверждённые численные значения и добавленная моделью пунктуация в цитатах. Диагностика ограниченной коррекции теперь перечисляет неверные цитаты/метрики; точные фрагменты исходника используются только как подсказки модели. Если после коррекции остались неподтверждённые числа, они заменяются на null с предупреждением, после чего весь Analysis повторно валидируется. Строгие правила цитат, ссылок и ручных правок сохранены.

86 backend-тестов прошли, включая сохранение подтверждённых замеров, отклонение поддельных цитат/ссылок и повторное отклонение чисел в ручных правках. Два живых прогона пользовательских примеров успешны: закупки 12 шагов / 5 потерь / 4 предложения, доставка 11 / 5 / 4.

Финальная проверка через публичный VPS также успешна: закупки — 21 шаг / 7 потерь / 7 предложений за 51,7 с; доставка — 16 / 9 / 6 за 33,4 с. Оба результата повторно прошли локальный строгий контракт, оба PDF содержат одну страницу. Различие числа элементов между запусками отражает вариативность модели. Независимое ревью выявило и закрыло проблему потери подтверждённых метрик в подсказке исправления цитат; повторное ревью существенных замечаний не выявило.
