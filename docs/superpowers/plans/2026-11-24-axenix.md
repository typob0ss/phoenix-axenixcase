# Axenix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax.

**Goal:** Полный локальный MVP по кейсу Axenix, готовый к демонстрации.
**Architecture:** React frontend и FastAPI backend обмениваются единым Analysis JSON. Честный деморежим независим от внешней LLM.
**Tech Stack:** React, TypeScript, Vite, FastAPI, Pydantic, pytest.
**Spec:** docs/superpowers/specs/2026-11-24-axenix-design.md

## Global Constraints
- Русский интерфейс; source text 1000–5000 символов, файл ≤2 МБ.
- Контракт docs/api-contract.md обязателен для frontend/backend.
- Не выдумывать метрики, цитаты проверять точно; явно обозначать demo/live.
- Команда хранится только в docs/team.md и может меняться.
- Каждый владеет своими файлами; не откатывать чужие изменения; работники не создают дополнительных агентов.

### Task 1: Сервер, достоверность, демоданные и отчёт
**Files:** backend/**, tests/**, requirements.txt (владелец backend worker).
**Interfaces:** Все API из docs/api-contract.md, Analysis как определён там.
- [ ] Написать pytest для точных цитат, неверных role/edge references, отрицательных метрик, трёх демо, режимов, TXT/DOCX импорта и лимитов, отчёта текущих исправлений. Наблюдать падение до реализации.
- [ ] Реализовать модели, демопримеры, извлечение через configurable OpenAI-compatible HTTP API, валидацию ссылок и цитат, ошибки без утечки секретов, DOCX ZIP limits, Markdown отчёт.
- [ ] `./.venv/bin/python -m pytest tests -q` проходит. Самопроверка контракта и отчёт координатору.

### Task 2: Интерфейс и визуализация
**Files:** src/**, index.html (владелец frontend worker).
**Interfaces:** API docs/api-contract.md; React entry src/main.tsx.
- [ ] Создать типы контракта и UI: загрузка/примеры, анализ, схема с дорожками, инспектор цитат и редактирования, узкие места, автоматизация, отчёт.
- [ ] Ошибки и ожидания видимы; деморежим явный. SVG и JSON выгружают текущее состояние, Markdown запрашивается с текущими данными. Редактирование шагов и переходов проходит /validate.
- [ ] `pnpm build` проходит. Проверить responsive, keyboard controls и empty/loading/error states. Отчёт координатору.

### Task 3: Интеграция, запуск, документация и сквозная проверка
**Files:** package.json, vite.config.ts, tsconfig*.json, scripts/**, README.md, docs/team.md (владелец координатор).
- [ ] Установить зависимости, создать reproducible lockfile и запуск одной командой. Сервер отдаёт dist после build.
- [ ] Проверить HTTP /health, три сценария, исправления, отчёт, ошибочные файлы, отсутствие ключа; в браузере протестировать основной сценарий и скачивания.
- [ ] Независимый reviewer проверяет фактические изменения против spec. Исправить существенные findings; повторить релевантные тесты и build.
- [ ] Зафиксировать прогресс/ограничения и дать пользователю адрес приложения и инструкции.
