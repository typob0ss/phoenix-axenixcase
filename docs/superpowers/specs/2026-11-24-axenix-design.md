# Процесс под микроскопом — согласованный MVP

Согласование: пользователь 24 ноября разрешил приступить к предложенному MVP и архитектуре. Защита 25 ноября около 10:00 МСК. Фамилии и обязанности команды предварительные, вне продукта.

## Результат
Русскоязычное веб-приложение превращает текст совещания (1000–5000 символов) в процесс с дорожками ролей, цитатами, узкими местами и предложениями автоматизации. Произвольный текст обрабатывается внешней LLM при настройке серверного ключа; без ключа доступны три явно обозначенных сохранённых демопримера. Никакой имитации живого ИИ.

## Архитектура
React + TypeScript + Vite, FastAPI + Pydantic. Общий контракт в docs/api-contract.md. Сервер выдаёт демоданные, принимает TXT/DOCX, вызывает OpenAI-compatible chat completions по серверной конфигурации, проверяет структуру, ссылки и точность цитат. JSON является единственным источником для схемы, аналитики и отчёта. Локальный сервер может отдавать собранный frontend из dist.

## Интерфейс
Светлая рабочая среда: графитовый текст, оранжевый акцент Axenix, левое меню, заголовок проекта. Ввод текста, карточки трёх примеров, явный статус режима. После анализа: схема с дорожками ролей и переходами, инспектор выбранного шага, узкие места, приоритеты автоматизации, отчёт. У шага редактируются название, роль, тип и цитата; переходы редактируются в инспекторе. Сохранять изменения только после серверной валидации. Редактирование делает производные рекомендации предварительными. Вся навигация клавиатурой, доступные подписи, адаптивный экран, состояния ошибок/загрузки.

## Данные и достоверность
Шаги: task, decision, wait, handoff, rework, manual_input. У каждого роль, цитата из source_text, уверенность 0..1 (оценка модели, не калиброванная вероятность), системы, документы, длительность либо null. У связей from/to, подпись и подтверждающая цитата. Рекомендации обозначены как гипотезы. Неизвестные время, стоимость и эффект — null, без вымышленных чисел. Деньги только при наличии основания и формулы. Не менее трёх подтверждённых узких мест и трёх предложений на каждом демопримере; для бедного произвольного текста разрешено меньше с предупреждением.

## Экспорт
JSON полного текущего результата; SVG текущей схемы; Markdown отчёта на одну страницу по объёму (около 500 слов). Экспорты используют текущее исправленное состояние. Отчёт перечисляет ключевые потери, предложения, цитаты, ограничения и способ расчёта метрик.

## Ошибки и запасной режим
LLM не настроена: понятное сообщение и выбор демопримеров. Сбой/тайм-аут LLM: ошибка без подмены произвольного текста сохранённым ответом. Неверные цитаты или граф не принимаются. Загрузка ограничена 2 МБ, текст 1000–5000 символов; DOCX проверяется как ZIP и ограничивается по распакованному размеру. API-ключ не попадает в browser/localStorage/git. Данные и персональные сведения не логируются.

## Приёмка
Три примера проходят полную валидацию. На схеме видны роли, развилка, ожидание и возврат. Выбор шага показывает точную цитату. Изменение шага отражается в схеме и выгрузках. Ошибочный файл и невалидный ответ модели объясняются пользователю. Backend-тесты проверяют валидацию, импорты, ошибки LLM и отчёт; frontend проходит TypeScript/build и браузерный сквозной сценарий. Перед передачей — отдельный независимый code review и исправление существенных замечаний.
