# Процесс под микроскопом · Axenix

ИИ-помощник для анализа бизнес-процессов: текст совещания → схема с дорожками ролей → подтверждённые цитатами узкие места → гипотезы автоматизации → отчёт.

## Быстрый локальный запуск

Нужны Python 3.11+ и Node.js 20.19+ (либо 22.12+). Из корня проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
corepack pnpm install --frozen-lockfile
corepack pnpm build
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000. В Codex на этой машине зависимости уже установлены локально; для сборки можно использовать `scripts/pnpm.sh build`, а для запуска `scripts/start.sh`.

Для разработки отдельно запустите API командой выше и frontend через `scripts/pnpm.sh dev`. Vite проксирует `/api` на порт 8000.

## Режимы анализа

- **Демонстрация** работает без ключей: три подготовленных примера банка, ритейла и HR. Результат явно помечен как сохранённый деморазбор.
- **Живой анализ** обрабатывает произвольный текст через серверный OpenAI-compatible API. Скопируйте `.env.example` в `.env`, задайте `LLM_API_KEY`, `LLM_BASE_URL` и `LLM_MODEL`, затем перезапустите сервер. API-ключ никогда не вводится в веб-интерфейсе.
- Недоступность модели не подменяется готовым ответом. Пользователь видит ошибку и может самостоятельно выбрать демопример.

Перед отправкой живого текста убедитесь, что вы вправе передавать его выбранному провайдеру. Приложение не сохраняет исходники на сервере; JSON и отчёт можно скачать вручную.

### ИИ-прокси чемпионата (ChatCI)

Адрес и имена моделей опубликованы в [инструкции организаторов](https://ideamillion.ci-sfedu.ru/#opencode). Для подключения сайта заполните локальный `.env`:

```dotenv
LLM_BASE_URL=https://chatci.online/proxy/v1
LLM_MODEL=deepseek-v4.1-flash
LLM_REASONING_EFFORT=none
LLM_API_KEY=
```

В `LLM_API_KEY` вставьте персональный ключ ИИ-прокси. Логин и начальный пароль ChatCI для серверного API не используются. `.env` исключён из Git; после изменения перезапустите сервер. Для другого провайдера оставьте `LLM_REASONING_EFFORT` пустым, если он не поддерживает этот параметр. Успешный `/api/health` подтверждает наличие настройки, а работоспособность модели проверяется анализом своего текста без выбора демопримера.

## Проверяемость

В разделе «Отчёт» доступен краткий PDF на одну страницу A4 и подробный Markdown. PDF показывает до трёх потерь и трёх предложений по приоритету; полные цитаты и основания доступны в JSON. Для репетиции живого анализа скачайте учебный TXT по ссылке под демопримерами или используйте `public/examples/axenix-defense.txt`. Он совпадает с сохранённым ритейл-примером, который служит резервом при недоступности модели. Все замеры этого примера вымышлены.

Цитаты проверяются как точные фрагменты исходного текста. Ссылки между шагами и ролями валидируются. Уверенность — субъективная оценка модели, не измеренная вероятность. Неизвестные метрики остаются неизвестными. Расчётные эффекты и автоматизация — гипотезы, требующие подтверждения владельцем процесса. После ручных изменений производные выводы требуют повторной проверки.

При единственном совпадении цитаты без учёта регистра сервер восстанавливает точное написание из исходника и добавляет предупреждение. Если ответ не проходит проверку структуры или оснований, модель получает одну попытку исправления по диагностике сервера; повторный ответ проходит те же проверки. Общий лимит ожидания — 95 секунд. Сетевые ошибки и ошибки авторизации повторно не отправляются.

## Проверки

```bash
.venv/bin/python -m pytest tests -q
node --test tests-ui/*.test.mjs
scripts/pnpm.sh build
```

Для frontend-тестов нужен Node.js 22.18+ с поддержкой TypeScript type stripping (проверено на Node.js 24). Сценарий демонстрации и проверки: [docs/demo.md](docs/demo.md). Контракт API: [docs/api-contract.md](docs/api-contract.md). Предварительный состав команды: [docs/team.md](docs/team.md).

## Границы прототипа

Без авторизации, многопользовательского хранения и импорта аудио. Схема служит для анализа процесса и не заявлена как формально валидная BPMN 2.0. Денежную экономию нельзя достоверно вычислить без объёмов операций и стоимости труда. Внешняя LLM требует отдельного ключа и доступного соединения; реальные ответы нуждаются в проверке человеком.
